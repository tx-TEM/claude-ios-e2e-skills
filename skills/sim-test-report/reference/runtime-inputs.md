# 入力が未定で終わったら値を決める

手順1で `run_flows.py` が「入力が未定」で実行を終えたときに読む。

```
iphone test_02 入力が未定（text:browse.search_field）。
いまこの画面に居る。見て打つ文字を決め、devices.iphone.inputs の "text:browse.search_field" に書き、同じコマンドをもう一度叩けば続きから走る。
iphone のここから先の 6件はまだ撮っていない。
```

止まるのは4つ。plan で `"runtime": true` を付けた**打つ文字**（`text`）と**見たい行が含む語**（`see`）、`"pick": 条件` を付けた**パターンの要素のどれを押すか**、`"in": {"pick": 条件}` を付けた**パターンの親（カルーセルなど）のどれの中でするか**。メッセージの「見て 〜を」がどれかを言っている。後者はメッセージに条件が出る（`見て条件「著者が複数いる作品」に合う browse.book_row.* を選んで、その ID（ダンプの id の欄をまるごと）を決め、devices.iphone.inputs の "tap:browse.book_row.*" に書き、…`）。**値の鍵は plan の `do` に書いた操作そのもの**（同じ項目で同じ操作が2回あれば2つ目は `#2` 付き、親を選ぶなら `<操作> in <親のパターン>`）。メッセージに出た鍵をそのまま使う。**条件の無いパターンの要素ではここに来ない** — `run_flows.py` が画面に見えている1件目を選び、`devices.<端末>.picked` に書いて先へ進む。

**`do` は1手ずつ流れていて、値を使う手の直前で止まっている。** `run_flows.py` がダンプを読んで対象（入力欄、パターンの行）が見えるところまで運び、そこで止まる。先へ走らせると画面が変わり、値を決めるために見ることができなくなるので、そこで終えている。**終えた時点で、アプリはその画面に居る。**

```bash
python3 <このスキルのディレクトリ>/scripts/maestrod.py inspect <UDID> peek
```

**その項目の `title` / `expect`（選ぶ行なら `pick` の条件も）と、ダンプの中身から値を決める。** 片方だけでは決まらない — テストケースが「何を確かめたいか」を、ダンプが「いまどんなデータが入っているか」を持っている。

```
expect: 入力した語を含む項目だけが並ぶ        →  複数の行に共通する部分（牛乳）
expect: 1件に絞れる                          →  1行にしか出ない語
see:    絞り込んだ語を含む行が出るまで待つ      →  行の ID に含まれる語（牛乳）。ID まるごとではない
pick:   著者が複数いる作品                    →  その条件を満たしている行の ID（browse.book_row.日本の昔話）
in:     10件に満たないカテゴリー               →  その条件を満たしている親の ID（recommend.carousel.8）
```

**ダンプに出ている文字列をそのまま使うとは限らない。** 上の1つ目は `牛乳, 1,000ml` と `低脂肪牛乳, 900ml` から `牛乳` を取り出している。**見たい行が含む語（`see`）は語だけを書く**（`牛乳`）。フローは「その語を含む ID の行」を探すので、ID をまるごと書くと当たらない。**打った語と同じとは限らない** — 作者で絞り込めば、行の ID は作品名。`run_flows.py` は書いた語を ID に含む行を上下の端まで探し、無ければ表示中の行を並べて止まる。並んだ行の ID の一部を書き直して叩き直す。**選ぶ行（`pick` / `in`）は、ダンプの id の欄をそのまま写す**（`browse.book_row.低脂肪牛乳`）。表示テキストではなく ID。パターンに当たらない ID（接頭辞を落とした、別の画面の ID）を書くと、`run_flows.py` は押さずに止まるので、直して叩き直す。**同じ ID の行が複数あるときは `browse.book_row.低脂肪牛乳#2` のように書く** — 画面に見えている同じ ID の行のうち、上から2件目。何も付けなければ見えているうちの1件目。`run_flows.py` が流す直前に画面を読み、同じ ID の行の何番目か（Maestro の `index`）を数えて押す。書いた行が画面に見えていなければ、その項目は撮れない。決めたら、マニフェストのその項目の `devices.<端末>.inputs` に書く。**値は端末ごと** — その端末の画面を見て決める。**決めた値は、正規表現のエスケープをかけずに書く。** 押す行のようにセレクタ（正規表現）に入る値は、`run_flows.py` がエスケープする。自分でもかけると二重になって当たらない。

```json
"devices": { "iphone": { "inputs": { "text:browse.search_field": "牛乳", "tap:browse.book_row.*": "browse.book_row.日本の昔話" } } }
```

**同じコマンドをもう一度叩く。** 止まった地点（項目と、その何手目か）はマニフェストの `resume` に記録されているので、撮り終えた端末は飛ばし、止まった端末の止まった手から走る。**手前は撮り直さない。**

- **未定の値の数だけ繰り返す。** 1回に1つずつ終える。1つの項目で2回以上止まることもある（打つ文字を決めてから、絞られた一覧で行を選ぶなど）
- **決めた値は手順2で使う。** 判定する側は「何を打ったか・なぜその行か」を知らないと期待と突き合わせられない（ダンプの入力欄にも出るが、なぜその値かは出ない）
- **sim-driver には渡さない。** 渡すと、そのテストケースの残りが全部モデルの仕事になる
