# 入力が未定で終わったら値を決める

手順1で `run_flows.py` が「入力が未定」で実行を終えたときに読む。

```
iphone test_02 入力が未定（text:browse.search_field）。
いまこの画面に居る。見て打つ文字を決め、同じコマンドに --value '<値>' を付けて叩き直す（続きから走る。値にシングルクォートが入るなら '\'' と書く）。
iphone のここから先の 6件はまだ撮っていない。
```

止まるのは2種類。plan で `"runtime": true` を付けた**打つ文字**（`text`）と、`"pick": 条件` を付けた**条件つきの選択**。条件つきの選択は、パターンの要素のどれを押すか（`tap`）・見るか（`see`）と、`"in": {"pick": 条件}` を付けたパターンの親（カルーセルなど）のどれの中でするか。条件つきの選択は、メッセージに条件と候補が出る（下の「条件つきの選択」）。**条件の無いパターンの要素ではここに来ない** — `run_flows.py` が画面に見えている1件目を選び、`devices.<端末>.picked` に書いて先へ進む。

**`do` は1手ずつ流れていて、値を使う手の直前で止まっている。** `run_flows.py` がダンプを読んで対象（入力欄、パターンの行）が見えるところまで運び、そこで止まる。条件つきの選択なら、並びの先頭（縦の一覧なら上の端、カルーセルなら先頭）まで戻してから止まる。先へ走らせると画面が変わり、値を決めるために見ることができなくなるので、そこで終えている。**終えた時点で、アプリはその画面に居る。**

## 返事は引数で渡す

**止まったときの問いへの返事は、同じコマンドに引数を付けて叩き直して渡す。マニフェストは手で書き換えない。**

```bash
python3 <このスキルのディレクトリ>/scripts/run_flows.py <出力先>/manifest.json --value '<値>'   # 決めた値
python3 <このスキルのディレクトリ>/scripts/run_flows.py <出力先>/manifest.json --next           # 候補に合うものが無い（条件つきの選択だけ）
```

- **どの項目・端末・鍵の値かは、`run_flows.py` が知っている。** 止まったときにマニフェストの `resume.ask` に書いてあるので、呼び出し元が場所を指し直さない。`--value` の値は `run_flows.py` が `devices.<端末>.inputs` に書き、そこから続きを走らせる
- **値は引用符で囲む。** 要素の ID には空白や記号（`・`、`「」`、`#2`）が入る。値にシングルクォートが入るなら `'\''` と書く
- **値は、正規表現のエスケープをかけずに渡す。** 押す行のようにセレクタ（正規表現）に入る値は、`run_flows.py` がエスケープする。自分でもかけると二重になって当たらない
- **値は端末ごと。** 止まった端末の画面を見て決める。端末ごとに止まるので、1回に1つずつ返す
- 止まっていないのに付けた、`--value` と `--next` を一緒に付けた、打つ文字で止まったのに `--next` を付けた、のどれも、走らせる前に止まる

## 値の決め方

```bash
python3 <このスキルのディレクトリ>/scripts/maestrod.py inspect <UDID> peek
```

**その項目の `title` / `expect`（選ぶ行なら `pick` の条件も）と、ダンプの中身から値を決める。** 片方だけでは決まらない — テストケースが「何を確かめたいか」を、ダンプが「いまどんなデータが入っているか」を持っている。

```
expect: 入力した語を含む項目だけが並ぶ        →  複数の行に共通する部分（牛乳）
expect: 1件に絞れる                          →  1行にしか出ない語
pick:   著者が複数いる作品                    →  その条件を満たしている行の ID（browse.book_row.日本の昔話）
in:     10件に満たないカテゴリー               →  その条件を満たしている親の ID（recommend.carousel.8）
```

**打つ文字は、ダンプに出ている文字列をそのまま使うとは限らない。** 上の1つ目は `牛乳, 1,000ml` と `低脂肪牛乳, 900ml` から `牛乳` を取り出している。

### 条件つきの選択

メッセージに、**いま画面に見えている行**が候補として並ぶ。行の ID、行の表示テキスト、行の枠の中にある要素の文字（`中:`）の順。条件つきの選択はダンプを読み直さなくても、ここから選べる。

```
iphone test_03 入力が未定（see:browse.book_row.*）。
いま画面に見えている行（候補）:
  - browse.book_row.吾輩は猫である ｜ 吾輩は猫である, 夏目 漱石
  - browse.book_row.日本の昔話 ｜ 日本の昔話, 柳田 國男、楠山 正雄
  - browse.book_row.牛乳 ｜ 牛乳, 1,000ml
  - browse.book_row.牛乳#2 ｜ 牛乳, 500ml
この中に条件「著者が複数いる作品の行」に合うものがあれば、その ID（候補の行の先頭。ダンプの id の欄をまるごと）を、同じコマンドに --value '<ID>' を付けて叩き直す（続きから走る。…）。
無ければ、同じコマンドに --next を付けて叩き直す（1画面送って、次の候補を出す）。
```

- **条件に合う行があれば、その値（`- ` の後ろの、最初の `｜` より前）を `--value` で渡す**（`--value 'browse.book_row.日本の昔話'`）。表示テキストではなく ID。同じ ID の行が複数見えていれば、2件目からは `#2` が付いて並ぶので、それも含めて写す
- **無ければ `--next` を付けて叩き直す。** `run_flows.py` が1画面だけ送り（縦の一覧なら画面、カルーセルなら親の中を横に）、また候補を出して止まる。まだ無ければ、また `--next` を付ける。**「無い」は値ではないので、`inputs` には残らない**（`inputs` は撮るときに決めた値の記録で、判定する側が読む）。送っても見えている行が変わらなければ端なので、その項目は「条件に合う要素が無かった」（`devices.<端末>.not_found`）として、最後に見た画面を撮って次へ進む。期待どおりのものが無かったので、判定で `NG` になる（撮り直しには回らない）。**送れるのは20画面まで** — 読み込みで伸び続ける一覧は端に着かないので、それを超えても同じ扱いにする
- **選ぶのは、候補に並んだ行からだけ。** 候補に無い行（前に見た行、画面の外の行）を渡さない。渡した行が画面に見えていなければ、その項目は撮れない
- 判断はダンプの文字でする。見た目でしか分からない条件（作品名が5行で切れている、など）は、ダンプからは選べない
- **候補が、操作の結果が出る前の画面に見えるとき**（絞り込む前の行が並んでいる、など）は、引数を付けずに叩き直す。先頭まで戻して読み直し、候補を出し直す。`--next` は1画面送るだけで、読み込みを待たない

パターンに当たらない ID（接頭辞を落とした、別の画面の ID）を渡すと、`run_flows.py` は押さずに止まるので、正しい ID を `--value` で渡し直す。`run_flows.py` は流す直前に画面を読み、同じ ID の行の何番目か（Maestro の `index`）を数えて押す・見る。

## 叩き直したあと

止まった地点（項目と、その何手目か）はマニフェストの `resume` に記録されているので、撮り終えた端末は飛ばし、止まった端末の止まった手から走る。**手前は撮り直さない。** 撮り直し（`RETAKE`）の途中で止まったときも同じ。撮り直しはテストケースの値を空にして始めるので、前の回に決めた値があっても止まって訊かれる（データが変わっていれば、前の回の値は当たらない）。

- **未定の値の数だけ繰り返す。** 1回に1つずつ終える。1つの項目で2回以上止まることもある（打つ文字を決めてから、絞られた一覧で行を選ぶなど）
- **決めた値は手順2で使う。** 判定する側は「何を打ったか・なぜその行か」を知らないと期待と突き合わせられない（ダンプの入力欄にも出るが、なぜその値かは出ない）。値そのものは `devices.<端末>.inputs` に残る
- **sim-driver には渡さない。** 渡すと、そのテストケースの残りが全部モデルの仕事になる
