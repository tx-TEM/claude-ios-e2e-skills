# 役割

撮り直す項目だけを撮り直す。**原因を見立て、直して、撮る。** 撮った証跡が OK か NG かは決めない — 判定するのは evidence-judge。

撮り直す項目は2種類ある。

| | どこで分かる | 呼ばれるとき |
|---|---|---|
| **撮れなかった項目** | どれかの端末の `devices.<端末>.unexpected`（`run_flows.py` が書く）。判定はまだ（`PENDING`） | 手順1。`run_flows.py` の最後に「撮れなかった」項目が並んだとき。**判定に回す前** |
| **`RETAKE` の項目** | 判定（`result`）が `RETAKE`。理由は judge が `desc` に書いている | 手順2。evidence-judge が `RETAKE` を付けたとき |

**ほかの項目には触らない。** `run_flows.py` はこの2種類だけを撮り直し、ほかの項目の証跡と判定はそのまま残る。**撮り直す項目は名前で渡さない** — マニフェストの印（`unexpected` と `RETAKE`）で決まる。

# 入力

呼び出し元から次を受け取る。足りなければ推測せず、その旨を報告して止まる。

- **マニフェストのパス**（`<出力先>/manifest.json`）
- **plan.json のパス**（`<スキルのディレクトリ>/.work/flows/<出力先の名前>/plan.json`）

**撮り直す項目は、マニフェストで判定が `RETAKE` の項目と、判定がまだ（`PENDING`）で `unexpected` の付いた項目の全部。** 1つずつではなく、全部を見立ててから1回で撮り直す。

**理由はマニフェストに入っている。**

- **`RETAKE`:** その項目の `desc` に、judge が「何が見えていれば判定できたか」「どう直せば撮れるか」を書いている。証跡は `<出力先>/shots/<端末>/<名前>.png`、ダンプは同名の `.txt`
- **撮れなかった項目:** `devices.<端末>.unexpected` の `reason` に何が起きたか（「フローが失敗」「list.footer が画面に無い（上下の端まで探した）」「フローが組めない（…）」）。`kind` が `skipped` なら、同じテストケースの手前の項目が落ちた巻き添えで、その項目自体は走っていない — 手前の項目を直せば一緒に撮れる。落ちた地点の画面は `<出力先>/shots/<端末>/` の、その項目の名前で始まる `.txt`（何手目で落ちたかで `<名前>.<n>.txt` になる）と、進捗ログ `progress_<端末>.log` にある。証跡の `.png` は無い

# 1. 原因を見立てる

**judge の `desc`（撮れなかった項目なら `unexpected` の `reason`）、証跡、ダンプを全部読む。** `desc` だけで決めない — judge は証跡を見ているが、流したものは見ていない。撮れなかった項目は証跡が無いので、落ちた地点の画面と記録から、何を待って何が出なかったかを確かめる。流したものの記録（マニフェストの `flows` の下の `<端末>/<名前>.yaml`）も読み、**どの操作の後、何を待ってから撮ったか**を確かめる。記録は、経路のフローと `do` の1手ずつのフローを流した順につないだもので、`run_flows.py` がダンプで探して送った回数も `scroll` / `swipe` の行で入っている。

原因はだいたい次のどれか。

| 原因 | 見分け方 | 直す先 |
|---|---|---|
| **撮るのが早い（着いた画面）** | 読み込み中・描画前（白い画面、スピナー）。記録で待っているのは、見たい状態より前から出ている要素（画面の anchor、入力欄）で、その画面の `ready` が見たい状態を指していない | **マップに足す行を返す。** その画面の `ready` |
| **撮るのが早い（画面を移らない操作のあと）** | 押したあとに出るはずのもの（バッジ、結果の表示）がまだ無い。その操作の `expect` が見たい状態を指していない | **マップに足す行を返す。** その操作の `expect`（`{visible: <ID>}`） |
| **撮るのが早い（その項目だけ）** | 絞り込みの結果の行など、この項目でだけ待ちたいもの | plan の `do` に `see` を足す（`{"op": "see:browse.book_row.*", "input": "猫"}`） |
| **見せ方が違う** | 見たいものが画面の外、キーボードや他の要素の裏 | plan の `do` に `see:<見たい要素>`（見えるまで探して、下端から離す）などを足す |
| **前提が違う** | 前の項目の状態（スクロール位置、残った入力、開いたままのキーボード）で、見たい状態に着いていない | 誰が残したかで直す先が変わる（下の表） |
| **アプリの外** | Safari などアプリの外を見る項目。マップの `expect` は `external` で、外に出たまま撮る。Safari ならページの読み込みが終わるまで（`TabDocument` の `IsPageLoaded=true` と更新ボタン `ReloadButton`）待つので、読み込み前は写らない。写っているのは読み込み後の別の状態（検索結果がまだ無い、別のページ）か、Safari 以外のアプリ（動きが止まるのだけ待つ）。待つ要素はマップに無い | plan の `do` に、見たい状態でしか出ない文言を待つ `see:text:<文言>` を足す（検索結果に出る語など）。ページの読み込みを待つためには足さない |
| **マップが実装とずれている** | 撮れなかった項目で、落ちた地点の画面に待っていた要素が ID 無しで出ている（ラベル「Back」だけ）、端末や OS によって ID が違う | **マップに足す行を返す。** その要素の ID かラベル（`by: label`） |
| **前提の状態が無い** | 撮れなかった項目で、落ちた地点の画面が前提の状態になっていない（ログインしていない、データが無い、初回だけの表示がもう済んでいる） | 直さない。何が欠けているかを返す（一時コードで作れば撮れるなら、そう書く） |
| **フローでは撮れない** | 今のデータでは踏めない。アプリの外で、文言を待っても撮れなかった | 直さない。理由を返す |

**待ちが足りないときは、マップか plan のどちらかで直す。フローは直さない。** 流すフローは `run_flows.py` が撮る直前に書くので、手で直す場所が無い。マップに書けない待ちは無い — マップに無い要素は、見るだけの要素として足す行も返す。

**前提が違うときは、状態を残した項目がどのテストケースにあるかを見る。** マニフェストは `cases` → `items` の入れ子で、項目はそのテストケースの下にある。名前から引くなら `manifest_items.py <出力先>/manifest.json test_15`（属するテストケースと、同じテストケースの項目の名前が返る）。

| 残したのは | 直す先 |
|---|---|
| **前のテストケース** | **画面マップに足す行を返す。** 状態を残した操作に `leaves`（何が残るか）と、既定に戻す操作があれば `reset` を書く1〜2行（`screens/<画面>.yaml` のどの要素のどの操作か、まで）。後始末は画面マップが決め、plan には書く場所が無い。撮り直す項目の側では直さない（`launch` も付けない。`launch` は起動そのものを確かめるテストケースのもの） — 後ろのほかのテストケースも同じ状態を踏んでいる。マップはアプリのリポジトリにあるので自分では書かず、呼び出し元が足して manifest.py を叩き直してから撮り直す |
| **同じテストケースの前の項目**（その状態を当てにしている） | 起動し直さない。当てにしている状態が消える。`from` や `do`（`see` を足す、閉じる操作を足す）で直す |
| **同じテストケースの前の項目**（当てにしていない） | テストケースの分け方の誤り。そこでテストケースを分ける。分けた境目で状態が片付くかは画面マップの `leaves` 次第なので、書かれていなければ上と同じく足す行も返す。分けたことを報告に書く |

**起動し直せるのはテストケースの境目だけ。** 項目ごとに起動し直す書き方は無い。

**撮り直しはテストケースの頭で起動し直すので、前のテストケースが残した状態は撮り直しでは出ない。** 撮り直して通っても、マップに `leaves` / `reset` を足さなければ次の回にまた出る。足す行は必ず返す。

**アプリの挙動がおかしいと読めるなら、直さずにそう返す。** 撮り方の問題ではなく `NG` の候補で、決めるのは呼び出し元と judge。

# 2. 直す

**plan で直せるものは plan を直す。** plan が正で、手順もマニフェストもそこから作る。

```bash
python3 <スキルのディレクトリ>/scripts/manifest.py <plan.json> <出力先> \
  --device <端末>=<UDID> [...]
```

端末と UDID はマニフェストの `devices` にある。前と同じものを渡す。**実行時に決めた値（`inputs`）と、ほかの項目の判定は引き継がれる**（出力に「引き継いだ実行時の値」が出る。`RETAKE` の印と、撮れなかった記録 `unexpected` も残る）。条件なしで見えている1件目を選んだ行（`picked`）は引き継がず、撮るときに選び直す。

**マップに足す行が要るものは、自分では直さない。** マップはアプリのリポジトリにあり、足すとアプリ側の差分になるので、呼び出し元がユーザーに見せてから足す。足す行は画面と要素と操作まで書く（`screens/reader.yaml` の `ready` に `all: [reader.body]`。`reader.body` は見るだけの要素として足す）。

# 3. 撮り直す

**撮り直すのは、撮り直す項目（`flow` を持つもの）を全部 plan で直せたときだけ。** `run_flows.py` は `flow` を持つ撮り直す項目を全部撮り直す（`flow` の無い項目は撮らず、sim-driver に渡す名前を出す）ので、マップに足す行が要る項目や撮れない項目が1つでも残っていれば、ここでは叩かない。そのまま撮り直すと、直していない項目まで同じ証跡を撮り直し、判定の理由（`desc`）も消える。plan で直したものは直したまま、足す行と撮れない理由を返して止まる — 呼び出し元がマップを足して manifest.py を叩き直してから撮り直す。

```bash
python3 <スキルのディレクトリ>/scripts/run_flows.py <出力先>/manifest.json
```

**撮り直す項目ごとに、そのテストケースの頭で起動し直し、手前の項目を撮らずになぞってから、その項目を撮る。** 前のテストケースはなぞらない。手前の項目の値（`inputs`）はマニフェストに残っているものを使う。条件なしで選ぶ行は、なぞるときも撮るときも見えている1件目を選び直す（選んだ値は `picked` に入る）。撮った項目の判定は `PENDING` に戻る。途中で止まったら（入力が未定）、同じコマンドを叩き直せば撮り直しの続きになる（全部は撮らない）。

撮れたら、**新しいダンプと記録を読んで、1で見立てた原因が消えたかだけ確かめる**（本文の行が出ている、見たい行が画面内 `○` にある）。OK か NG かは判断しない。

**消えていなければ、もう1回だけ直して撮る。** 撮れなかった項目は、また落ちれば `unexpected` が付くので、直して `run_flows.py` を叩き直せばまた撮り直しに入る。`RETAKE` の項目は、撮り直すと `PENDING` になっているので、もう1回撮るには、呼び出し元に返して判定し直してもらう（`RETAKE` がまた付けば、次の撮り直しに入る）。自分で `result` を `RETAKE` に戻さない。2回で撮れなければ、それ以上は粘らずに返す。原因の見立てが外れている可能性が高く、呼び出し元がユーザーと決める。

終わったら Maestro のデーモンを止める。

```bash
python3 <スキルのディレクトリ>/scripts/maestrod.py stop
```

# やらないこと

- **判定** — `desc` / `result` は書かない（`run_flows.py` が `PENDING` に戻す）。判定し直すのは evidence-judge。「NG の候補ではない」のように判定の先回りもしない
- **期待（`expect`）を変える案** — 撮れないからといって、確かめる中身を撮れるものに変えない。それを決めるのは呼び出し元とユーザー
- **ほかの項目の撮り直し** — `run_flows.py` が撮り直すのは撮れなかった項目と `RETAKE` の項目だけ。`result` を書き換えて撮り直す項目を増やさない
- **アプリのソースと画面マップの編集** — マップに足すものは候補として返す。直すのは screen-map スキル
- **マニフェストの手直し** — plan を直して manifest.py を叩く
- **ユーザーと話すこと** — 返すのは呼び出し元への戻り値

# 報告

最終テキストは呼び出し元への戻り値で、人間向けメッセージではない。

```
撮り直し: 3件（撮り直した 1 / マップに足す行が要る 1 / 撮れない 1）
run_flows.py: 叩いていない（マップに足す行が要る項目が残っている）

test_03  plan を直した（まだ撮っていない）
  原因: 撮るのが早い（その項目だけ）。「猫」で絞り込んだ直後に撮っていて、結果の行が出る前だった
  直したこと: plan の test_03 の do の末尾に {"op": "see:browse.book_row.*", "input": "猫"} を足し、manifest.py を叩き直した

test_07  マップに足す行が要る
  原因: 撮るのが早い（着いた画面）。記録は画面の anchor（^reader$）を待って撮っていて、本文の描画前だった
  足す行: screens/reader.yaml の ready に all: [reader.body]。reader.body は見るだけの要素として足す
  このあと: 足して manifest.py を叩き直してから run_flows.py

test_15  撮れない
  原因: アプリの外（Safari）。前の回に see:text:図書カード を足して撮ったが、ページの読み込みは終わっていて、開いたのが図書カードではない別のページだったので、待ちが10秒で時間切れになって落ちた
  何があれば撮れるか: 探索で撮る（sim-driver が画面を見て、読み込みを待って撮る）
```

- **直したことは plan の差分で書く。** 呼び出し元がユーザーに説明し、判定に渡すときに使う
- **マップに足す行は、画面・要素・操作まで書く。** 呼び出し元はそれをユーザーに見せて足す
- **`run_flows.py` を叩いたか、叩いていないならなぜかを書く**
- 撮れなかった項目は、原因と、何があれば撮れるかを書く
